01 · Business Problem
The Problem
Organizational/family knowledge — financial tracking, project docs, historical records — lives scattered across 8 Confluence spaces with dozens of pages and nested tables. Finding a specific fact (e.g. “what did we spend on X in 2022”) means manually opening pages and scanning tables — slow and error-prone. On top of that, CORS blocks any browser-based tool from calling the Confluence API directly, so a simple client-side script can't just fetch the data itself.
The Solution
A lightweight local proxy server bridges the browser to the Confluence Cloud REST API. A single agent takes a natural-language question, runs a CQL full-site search via the proxy to find and fetch the most relevant pages, then uses Claude to synthesize a grounded, cited answer — no manual page-hunting.
02 · Solution Description
Why Not Manual Search?
8 spaces, dozens of pages — no single search finds the right table
Answers require scanning nested tables across multiple pages
Confluence Cloud API blocks direct browser calls (CORS)
Why Proxy + Agent?
Local Flask proxy sidesteps CORS with server-side auth
CQL search narrows 8 spaces down to the handful of relevant pages
Claude answers only from retrieved text and cites the source page(s)

Agent Loop — Claude drives its own retrieval
This isn't a fixed search-then-answer pipeline. Claude is given search_confluence and get_page as real tools (Anthropic tool-use) and runs its own loop: search, look at what came back, search again with different keywords or open more pages if needed, and only answer once it actually has enough — up to 5 turns per question.

The proxy's result is sent back to Claude as a tool_result, and the loop repeats until Claude stops calling tools and returns a final answer — visible live in the Live Agent tab as a step-by-step trace above each response.
Tools Exposed to Claude
ToolWhat it does
search_confluence(query) Proxies to GET /search?q= — runs a title-match and a text-match CQL search (title ~ / text ~ "..." and type=page) and merges them, title matches first, so an exact-title page always surfaces even when it ranks low on body-text relevance. Returns up to 8 {id, title, space, url} results.
get_page(page_id) Proxies to GET /page/<id> — fetches one page's body.storage, strips HTML tags, and returns {id, title, space, url, text}, text truncated to the first 8,000 characters.
The proxy also strips filler/question words (“tell”, “me”, “about”, “what”, etc.) from whatever query it receives before building CQL — Confluence's text ~ "..." requires every word in the phrase to literally co-occur, so an unfiltered natural-language question can silently exclude the page you're actually asking about. Claude is also instructed to search with focused keywords rather than a full sentence in the first place.
Local-Dev-Only Demo
The proxy must be running locally for the Live Agent tab to work: python confluence_proxy.py (listens on port 5175). This is a local-dev-only demo, not a hosted backend — the Confluence API token lives in a local .env file that is never committed to the repo and never exposed to the browser. If the proxy isn't running, the Live Agent tab will tell you instead of failing silently.

Confluence Knowledge Agent — ask a question about anything tracked in the Confluence knowledge base (financial tracking, project docs, historical records) and it will search live pages, retrieve the relevant excerpts, and answer with citations. Requires the local proxy (see the Architecture tab).
